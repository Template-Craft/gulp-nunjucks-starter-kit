# Документация по системе сборки

**Версия:** v2025.08.12  
**Дата:** 2025-08-12

Этот документ описывает модули системы сборки, расположенные в `gulp/utils/`, а также связанные задачи и конфигурацию проекта. Цель — быстрые и предсказуемые пересборки в режиме **dev** (паритет скорости для лендингов и многостраничных сайтов) и прозрачная модель зависимостей для шаблонов Nunjucks.

---

## Обзор

HTML‑сборка основана на Nunjucks с **точечным ререндером**: пересобираются только те страницы, на которые реально повлияли изменения. Поддерживается **карта зависимостей** между страницами и тремя типами строительных блоков:

- **Компоненты:** `src/views/components/**`
- **Секции:** `src/views/sections/**` (одностраничный и многостраничный режимы)
- **Шаблоны:** `src/views/templates/**`

Карта зависимостей кешируется в памяти для скорости и инкрементально обновляется при изменениях файлов.

### Ключевые пути

- Корень Nunjucks: `src/views/`
- Страницы: `src/views/pages/**/*.njk`
- Данные JSON: `src/views/data/**/*.json`
- Компоненты: `src/views/components/**`
- Секции: `src/views/sections/**`
- Шаблоны: `src/views/templates/**`

## Модуль: `gulp/utils/dependencyCache.mjs`

**Назначение:** Кеш в памяти для карты зависимостей. Позволяет избежать полного пересчёта карты, когда ничего не менялось.

**Структура кеша:**
```js
{
  components: Map<string, string[]>, // компонент -> список файлов‑потребителей
  sections:   Map<string, string[]>, // секция    -> список страниц, где используется
  templates:  Map<string, string[]>, // шаблон    -> список зависимых (страницы/секции)
  timestamp:  number
}
```

**Особенности**
- Бюджет памяти ~300 МБ.
- Строгая проверка равенства (`isSameMap`) перед перезаписью кеша.
- Чистые и ненавязчивые логи (включая логи cache hit — видно, что кеш используется).

**API**
- `initDependencyCacheIfNeeded()` — инициализация один раз (старт dev‑сессии).
- `getDependencyCache()` — получить текущую карту.
- `setDependencyCache(map)` — записать новую карту (с защитой от лишних перезаписей).
- `clearDependencyCache()` — очистка вручную.

## Модуль: `gulp/utils/buildDependencyMap.mjs`

**Назначение:** Построение (или частичное построение) глобальной карты зависимостей путём сканирования проекта.

**Сигнатура:**
```js
const map = await buildDependencyMap({
  includeComponents: boolean,
  includeSections:   boolean,
  includeTemplates:  boolean,
});
```

**Возвращает:** Объект с тремя `Map` (`components`, `sections`, `templates`) и служебными полями, совместимый с `dependencyCache`.

**Заметки по производительности**
- Используются таргетированные glob’ы и игнор‑листы для сокращения I/O.
- В dev по возможности вызывать один раз на батч; для точечных апдейтов опираться на `updateDependencyMap`.

---

## Модуль: `gulp/utils/updateDependencyMap.mjs`

**Назначение:** Инкрементальное обновление карты зависимостей для одного изменённого элемента.

**Сигнатура:**
```js
await updateDependencyMap({ type, name });
// type: 'component' | 'section' | 'template'
// name: логическое имя, например 'Button', 'hero', '_title'
```

**Поведение**
- Пересчитывает использования **только** для переданного элемента (через `find*Usages`).
- Удаляет запись, если использования не найдены (не держим «мёртвые» узлы).

## Модуль: `gulp/utils/findComponentUsages.mjs`

**Назначение:** Поиск мест использования компонентов, например через `getComponent('ComponentName')` или эквивалентные конструкции.

**Правила и оптимизации**
- По правилу проекта **шаблоны не вызывают компоненты**. Безопасно **игнорируем** `templates/**` здесь для ускорения сканирования.
- Определяет использования внутри секций и напрямую в страницах.

**Возвращает:** `Map<componentName, string[]>`

---

## Модуль: `gulp/utils/findSectionUsages.mjs`

**Назначение:** Поиск использования секций, разрешаемых через `getSection(pageName, sectionName)`.

**Поддерживаемые режимы**
- **Одиночный (лендинг):** `sections/_section.njk`
- **Многостраничный:** `sections/<pageName>/_section.njk`

**Краевые случаи**
- Компоненты внутри секций.
- Шаблоны внутри секций.
- Корректное разворачивание цепочек вида *компонент → секция → страница* и *шаблон → секция → страница*.

**Возвращает:** `Map<sectionName, string[]>`

---

## Модуль: `gulp/utils/findTemplatesUsages.mjs`

**Назначение:** Поиск мест, где шаблоны из `src/views/templates/` подключаются напрямую (include/import). Шаблоны могут использоваться страницами, секциями, компонентами и другими шаблонами (только прямые include/import).

**Правила проекта**
- Внутри шаблонов **нет** вызовов компонентов (никаких `getComponent(...)`).
- Шаблоны подключаются напрямую (нет helper’а `getTemplate(...)`).

**Возвращает:** `Map<templateName, string[]>`

---

## Модуль: `gulp/utils/getSectionNameFromPath.mjs`

**Назначение:** Извлечь логическое имя секции из пути к файлу.

**Примеры**
- `src/views/sections/_hero.njk` -> `hero`
- `src/views/sections/home/_hero.njk` -> `hero`

---

## Модуль: `config/settings.mjs`

**Назначение:** Глобальные флаги сборки (режимы и отладка).

**Ключевой флаг**
`gulp/config/settings.mjs`

```js
export const settings = {
  isMultipage: false, // false = langing pages, true = multipage project
  ...
};
```
Используется `findSectionUsages` и логикой рендера для интерпретации путей секций.

Можно добавить дополнительные флаги, например `debug`, чтобы увеличивать уровень логов, менять тип sourcemaps и т.д.

## Задача: `gulp/tasks/templates.mjs`

**Ответственности**
1. **Классификация изменений:** `detectChangeType(file)` →  
   `component-json` | `global-json` | `page` | `template` | `full/unknown`.
2. **Определение целей:** `resolveRenderTargets(type, file)` →  
   - JSON страницы с именем как у `pages/<name>.njk` → пересобираем **только** эту страницу.  
   - JSON с именем компонента/секции/шаблона → пересобираем связанные страницы (через карту зависимостей).  
   - Изменение компонента/секции/шаблона → пересобираем прямых потребителей; если потребитель — секция, разворачиваем дальше до страниц.  
   - Глобальные JSON (`Global.json`, `Common.json`) → пересборка всех страниц.
3. **Рендеринг:** `runRender(globOrFiles, options)` → HTML в `dist`.

**Dev vs Build**
- **Dev:** максимально быстро (без beautify/minify HTML). Пересобираем только нужные страницы.
- **Build:** полный beautify/minify, без кеша компиляции.

## Задача: `gulp/tasks/styles.mjs`

**Назначение:** Компиляция SCSS → CSS. В проекте используется единый входной файл `main.scss`, который через `@use` подтягивает стили всех страниц и базовые модули (миксины, сбросы и т.д.).

**Особенности проекта**
- Структура SCSS разбита на директории по страницам и общие модули.
- При разработке компилируется только `main.scss` (изменения в partial'ах приводят к пересборке `main.scss`).
- Поддерживаются sourcemaps и HMR.

**PostCSS‑конвейер**
- `autoprefixer({ cascade: true, grid: true, overrideBrowserslist: ['last 6 versions'] })`
- `postcss-sort-media-queries({ sort: 'desktop-first' })`
- `cssnano(...)` **только в build**, в **dev отключён** (ускорение пересборок).

**Dev vs Build**
- **Dev:**  
  - `cssnano` выключен; сохраняются читаемые стили.  
  - Быстрые sourcemaps (inline или на усмотрение задачи).  
  - Рекомпиляция только `main.scss` при изменениях partial'ов.
- **Build:**  
  - Включён `cssnano` (advanced preset, удаление комментариев и т.п.).  
  - Оптимизации для продакшена, возможно — отдельные sourcemaps/без sourcemaps.

**Рекомендации**
- Использовать `dart-sass` как компилятор (используется сейчас).  
- Проверить, что task не прогоняет по ошибке все SCSS‑файлы — только `main.scss`.  
- В dev не включать дополнительные тяжёлые плагины PostCSS (оставить только перечисленные).

## Рекомендации по производительности (текущая база)

- **JavaScript (webpack):**
  - Dev sourcemaps: `eval-cheap-module-source-map`.
  - Постоянный кэш: `cache: { type: 'filesystem' }`.
- **CSS:**
  - `cssnano` только в **build**; в dev — выключен.
- **Ассеты (изображения/шрифты):**
  - Копировать только изменённые файлы через `since: lastRun(task)`.
- **Поиски (utils):**
  - В `findComponentUsages` игнорировать `templates/**` (безопасно по правилам проекта).

## Диагностика

- **«На первом прогоне ничего не отрендерилось».**  
  Проверь, что `app.path.src.nunjucksPages` — валидный glob (например, `src/views/pages/**/*.njk`), и что `cwd` процесса совпадает с корнем проекта.

- **«Изменение секции не пересобирает страницу».**  
  Убедись, что `findSectionUsages` видит шаблоны/компоненты внутри секций (в текущей версии это учтено). Проверь, что `updateDependencyMap` удаляет «пустые» узлы.

- **«Dev‑пересборка всё ещё медленная».**  
  Убедись, что `cssnano` выключен в dev, webpack использует быстрые sourcemaps + постоянный кэш, а задачи ассетов копируют только изменённые файлы.
