# Terminology

Единая терминология, используемая во всей документации.

---

## Architectural Approach

Совокупность архитектурных принципов и решений, определяющих организацию проекта независимо от используемых инструментов.

---

## Build System

Реализация архитектурного подхода: автоматизирует разработку, анализ зависимостей и сборку.

---

## Page

Шаблон — точка входа при генерации отдельной HTML-страницы.

---

## Section

Крупный функциональный блок страницы. Объединяет связанные компоненты, данные и другие шаблоны в рамках одной задачи (Hero, About, Gallery и т.п.).

---

## Component

Повторно используемый элемент интерфейса с собственной структурой и зоной ответственности. Может использоваться разными страницами и секциями.

---

## Template

Инфраструктурный шаблон для вспомогательных задач (`<head>`, подключение скриптов и т.п.). Не является самостоятельной страницей или элементом интерфейса.

---

## Data

Структурированные данные (JSON), используемые при рендеринге. Источник данных отделён от шаблонов.

---

## Template API

Набор функций (`getComponent`, `getSection`, `getTemplate`, `getData`), через которые шаблоны обращаются к архитектурным сущностям по имени, а не по пути к файлу.

---

## Dependency Graph

Карта связей между архитектурными сущностями проекта. Используется для анализа изменений и определения минимального набора файлов для пересборки.

---

## Incremental Build

Режим сборки, при котором пересобираются только страницы, реально затронутые изменением.

---

## Build Pipeline

Последовательность этапов обработки проекта во время разработки и сборки.
