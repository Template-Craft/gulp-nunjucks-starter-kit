# Architectural Approach

## Введение

Архитектурный подход — основа, вокруг которой построена вся Build System.

Он определяет организацию проекта, роли его элементов и принципы их взаимодействия. Build System не формирует эти правила, а реализует их и автоматизирует связанные с ними процессы.

По этой причине архитектурный подход рассматривается как первичный уровень системы, а выбор конкретных инструментов — как его следствие.

## Почему архитектура важнее инструментов

При разработке небольших сайтов выбор системы сборки или шаблонизатора часто кажется главным решением. Однако по мере роста проекта становится очевидно, что долгосрочную сложность определяют не инструменты, а архитектура.

Именно архитектура отвечает на вопросы:

- как организован проект;
- какие роли выполняют различные типы шаблонов;
- где располагаются данные;
- как обеспечивается повторное использование кода;
- каким образом элементы проекта взаимодействуют друг с другом;
- как изменения распространяются по системе.

Если эти решения отсутствуют или принимаются стихийно, проект постепенно теряет предсказуемость независимо от выбранного стека технологий.

## Архитектура определяет инструменты

В рамках данного проекта выбор технологий никогда не являлся отправной точкой.

Архитектурный подход формировался на протяжении многих лет в реальных проектах. По мере его развития становилось понятно, какие требования предъявляются к шаблонизатору, системе сборки и остальным инструментам.

Именно поэтому Build System построена на Gulp и Nunjucks. Они были выбраны потому, что позволяют реализовать сформировавшиеся архитектурные принципы, а не потому, что определяют архитектуру проекта.

При необходимости конкретные инструменты могут быть заменены без изменения самого архитектурного подхода.

## Архитектурный подход как основа Build System

Все возможности Build System являются следствием архитектурного подхода.

Из него последовательно вытекают:

- организация структуры проекта;
- разделение шаблонов по их ответственности;
- Template API;
- Dependency Graph;
- Incremental Build;
- процесс сборки.

Каждый следующий уровень опирается на предыдущий. Именно поэтому Build System рассматривается как реализация архитектурного подхода, а не как самостоятельный набор инструментов.
