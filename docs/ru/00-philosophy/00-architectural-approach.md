# Architectural Approach

Архитектурный подход — основа, вокруг которой построена вся Build System. Он определяет организацию проекта, роли его элементов и принципы их взаимодействия. Build System не придумывает эти правила заново — она их реализует и автоматизирует.

## Почему архитектура важнее инструментов

При разработке небольших сайтов выбор системы сборки или шаблонизатора часто кажется главным решением. По мере роста проекта становится очевидно, что долгосрочную сложность определяют не инструменты, а архитектура — она отвечает на вопросы:

- как организован проект;
- какие роли выполняют разные типы шаблонов;
- где располагаются данные;
- как обеспечивается повторное использование кода;
- как элементы проекта взаимодействуют друг с другом;
- как изменения распространяются по системе.

Если эти решения отсутствуют или принимаются стихийно, проект теряет предсказуемость независимо от выбранного стека.

## Архитектура определяет инструменты

Build System построена на Gulp и Nunjucks потому, что они позволяют реализовать уже сформировавшийся архитектурный подход — а не потому, что определяют его. При необходимости инструменты можно заменить без изменения самой архитектуры.

## Что из этого следует

Все возможности Build System — следствие архитектурного подхода, а не независимый набор функций:

```text
Архитектура
      │
      ▼
Структура проекта
      │
      ▼
Разделение шаблонов по ответственности (Pages / Sections / Components / Templates)
      │
      ▼
Template API
      │
      ▼
Dependency Graph
      │
      ▼
Incremental Build
      │
      ▼
Build Pipeline
```

Каждый следующий уровень опирается на предыдущий — поэтому следующие разделы документации рассматривают их именно в этом порядке.
