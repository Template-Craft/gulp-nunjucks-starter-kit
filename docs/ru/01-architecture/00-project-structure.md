# Project Structure

Архитектурный подход определяет не только правила взаимодействия элементов проекта, но и их физическую организацию в файловой системе.

Структура каталогов является частью архитектуры и отражает разделение ответственности между различными типами ресурсов. Каждый каталог имеет строго определённое назначение, что делает проект предсказуемым и упрощает его сопровождение.

Важно понимать, что структура проекта не является случайным набором директорий или рекомендацией по организации файлов. Она представляет собой модель, вокруг которой построена вся Build System.

## Основные принципы

Организация проекта основана на нескольких правилах:

- каждый каталог отвечает только за один тип сущностей;
- разные архитектурные сущности не смешиваются между собой;
- расположение файлов отражает их роль в системе;
- Build System может определить назначение файла по его расположению.

Такой подход позволяет избежать неоднозначности и значительно упрощает анализ зависимостей между элементами проекта.

## Архитектурные области

Проект разделён на несколько независимых областей.

### Views

Содержит шаблоны проекта и связанные с ними данные.

Именно эта часть проекта определяет структуру сайта и является основным объектом работы Build System.

### Assets

Содержит ресурсы, используемые во время разработки и сборки.

К ним относятся стили, изображения, шрифты, SVG-спрайты и другие статические файлы.

### Scripts

Содержит исходный код клиентской части проекта.

Build System рассматривает его как отдельную архитектурную область, не смешивая со структурой шаблонов.

## Архитектурные элементы

Внутри каталога `views` каждый тип шаблонов имеет собственную область ответственности.

- Pages — точки входа проекта.
- Sections — крупные функциональные части страниц.
- Components — повторно используемые элементы интерфейса.
- Templates — инфраструктурные шаблоны.
- Data — источник данных.

Назначение каждого из этих элементов подробно рассматривается в следующих разделах документации.

## Почему это важно

Build System не анализирует проект как произвольный набор файлов.

Она работает с архитектурной моделью проекта.

Благодаря этому становится возможным анализ зависимостей между элементами, построение Dependency Graph и выполнение Incremental Build.
