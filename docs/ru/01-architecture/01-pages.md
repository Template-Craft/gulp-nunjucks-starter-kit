# Pages

Pages являются точками входа Build System.

Каждый файл внутри каталога `views/pages` представляет отдельную HTML-страницу, которая будет создана во время сборки проекта.

## Ответственность

Page отвечает только за композицию страницы.

Она определяет:

- какие Sections используются;
- в каком порядке они располагаются;
- какие данные необходимы странице;
- какой Template используется в качестве основы.

Page не должна содержать сложную логику или повторно используемую разметку.

Такая ответственность принадлежит другим архитектурным элементам.

## Композиция страницы

Страница формируется путём объединения независимых Sections.

Каждая Section отвечает только за собственную функциональную область.

Такой подход позволяет свободно изменять структуру страниц, повторно использовать Sections и минимизировать дублирование шаблонов.

## Взаимодействие с данными

Page может использовать собственные данные, глобальные данные и данные, необходимые отдельным архитектурным элементам.

При этом сама страница не должна становиться источником данных для других частей проекта.

## Взаимодействие с Build System

Для Build System Page является конечной целью процесса сборки.

Именно страницы участвуют в анализе зависимостей и являются объектами Incremental Build.

При изменении любого компонента, секции, шаблона или источника данных Build System определяет, какие Pages зависят от этих изменений, и пересобирает только их.

## Почему Pages существуют отдельно

Выделение Pages в самостоятельную архитектурную сущность позволяет отделить структуру сайта от реализации отдельных элементов интерфейса.

Благодаря этому каждая страница остаётся компактной, легко читается и содержит только информацию о своей композиции, а не детали реализации составляющих её элементов.
