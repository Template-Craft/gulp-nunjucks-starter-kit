# Data

Data представляет собой архитектурную область проекта, отвечающую за хранение данных, используемых при построении страниц.

Архитектурный подход рассматривает данные как самостоятельную часть системы, отделённую от шаблонов и других ресурсов.

## Ответственность

Data содержит информацию, необходимую для рендеринга архитектурных сущностей.

Шаблоны определяют структуру.

Data предоставляет содержимое.

Такое разделение делает архитектуру более понятной и упрощает сопровождение проекта.

## Уровни данных

Build System поддерживает несколько уровней данных.

Глобальные источники данных содержат информацию, используемую различными частями проекта.

Локальные источники данных принадлежат конкретным архитектурным сущностям.

Например, компонент может иметь собственный файл данных с тем же именем, что и сам компонент.

Несмотря на то, что все JSON-файлы располагаются в едином каталоге `src/views/data`, архитектурно они принадлежат соответствующим сущностям проекта.

## Соглашение об именовании

Для локальных источников данных используется соглашение об именовании.

Имя JSON-файла должно полностью совпадать с именем соответствующей архитектурной сущности.

Это позволяет Build System автоматически связывать данные с компонентами и другими элементами архитектуры без дополнительной конфигурации.

## Почему Data существует отдельно

Выделение данных в самостоятельную архитектурную область позволяет отделить содержимое проекта от его представления.

Такой подход делает архитектуру более гибкой, облегчает повторное использование информации и создаёт основу для анализа зависимостей, выполняемого Build System.
