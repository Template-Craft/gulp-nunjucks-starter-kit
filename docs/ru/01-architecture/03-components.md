# Components

Components представляют собой повторно используемые архитектурные сущности проекта.

Каждый Component объединяет всё, что относится к реализации одного элемента интерфейса, сохраняя при этом единую область ответственности и идентичность.

## Ответственность

Component отвечает за реализацию отдельного элемента пользовательского интерфейса.

Он не должен определять структуру страницы или выполнять роль крупного функционального блока. Эти задачи относятся к другим архитектурным сущностям.

## Архитектурная сущность

Component не является отдельным файлом.

Он представляет собой архитектурную сущность, которая может включать несколько файлов, реализующих различные аспекты компонента.

Например:

```text
Header/
├── Header.njk
├── _Header.scss
└── Header.js
```

При наличии собственных данных компонент также использует источник данных с тем же именем.

Например:

```text
src/views/data/
└── Header.json
```

Несмотря на физическое расположение в другом каталоге, этот файл архитектурно принадлежит компоненту `Header`.

## Соглашение об именовании

Имя компонента является его уникальным идентификатором.

Все файлы, относящиеся к компоненту, используют одно и то же имя и рассматриваются Build System как единая архитектурная сущность.

Благодаря этому дополнительные конфигурационные файлы или регистрация компонентов не требуются.

## Повторное использование

Components предназначены для повторного использования различными Sections и Pages.

Component не должен зависеть от конкретного места использования и должен получать необходимые данные через архитектурные механизмы Build System.

## Почему Components существуют отдельно

Выделение компонентов в самостоятельную архитектурную сущность позволяет отделить реализацию отдельных элементов интерфейса от композиции страницы.

Такой подход упрощает сопровождение проекта, делает повторное использование естественной частью архитектуры и предоставляет Build System возможность анализировать зависимости между архитектурными сущностями.
