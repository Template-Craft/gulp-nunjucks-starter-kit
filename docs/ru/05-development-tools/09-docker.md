# Docker (опционально)

Способ запустить Build System полностью изолированно от хостового Node/npm. **Не используется по умолчанию** — обычный путь остаётся `npm install && npm run dev`. Docker полезен тем, кто хочет развернуть инструмент без установки Node/npm на своей машине (безопасность/изоляция), а не ради скорости — на Linux нативный запуск и так максимально быстрый (проект **Linux-first**, см. README).

## Запуск

```bash
docker compose build
docker compose up
```

Откройте `http://localhost:8080` — дальше работаете с `src/` на хосте как обычно: правки видны внутри контейнера мгновенно (bind-mount), BrowserSync сам перезагрузит страницу.

Продакшен-сборка тем же образом, без отдельного сервиса:

```bash
docker compose run --rm dev npm run build
```

## Как это устроено

- **Образ** — `node:22-slim` (не Alpine): нативные зависимости (`@parcel/watcher` и др.) поставляются прекомпилированными под glibc.
- **`node_modules`** — отдельный volume, не bind-mount с хоста: нативные бинарники, собранные на хосте (особенно macOS/Windows), не запустятся в Linux-контейнере.
- **Непривилегированный юзер** — контейнер работает под `node` (1000:1000), не root. Если UID/GID на хосте другой (`id -u`/`id -g`), создайте рядом `.env`:
  ```env
  UID=1001
  GID=1001
  ```
  и пересоберите образ — иначе запись в примонтированный `build/` упрётся в permission denied.

## Нюансы по ОС

На **macOS/Windows** (Docker Desktop) живая перезагрузка файлов может срабатывать с задержкой из-за виртуализации ФС. Если `src/`-правки не триггерят пересборку — раскомментируйте в `docker-compose.yml`:

```yaml
environment:
  CHOKIDAR_USEPOLLING: '1'
```

На **Linux** это не требуется — bind-mount работает нативно, без виртуализации.

## Лимит памяти в контейнере

`settings.monitor.maxMemoryMB` (Runtime Monitor) по умолчанию считается от памяти **хоста** (`os.totalmem()`), а не от лимита контейнера. Если реально ограничиваете контейнер (`mem_limit`/`deploy.resources`), задайте тот же лимит явно:

```yaml
environment:
  DOCKER_MEM_LIMIT_MB: '2048'
mem_limit: 2048m
```

иначе порог никогда не сработает, даже если контейнеру реально не хватает памяти.

## Чего нет

Системные уведомления (`node-notifier`) внутри контейнера не показываются — нет ни `notify-send`, ни доступа к D-Bus сессии хоста. Вся та же информация и так видна в терминале (цветной вывод сохраняется, `tty: true`) — пробрасывать D-Bus хоста внутрь контейнера ради уведомлений не стоит, это осознанно ослабляет ту самую изоляцию, ради которой Docker-опция и существует.
