# Настройки Build System

Все параметры, влияющие на поведение Build System, собраны в одном месте:

```text
gulp/config/settings.mjs
```

## Режим проекта

```js
isMultipage; // false = Landing Page, true = Multipage Project
```

Некоторые механизмы (например, адресация Sections через `getSection`) ведут себя по-разному в зависимости от этого флага.

## Язык консольного вывода

```js
locale: 'en'; // 'en' | 'ru' | 'pl' | ...
```

Переводы хранятся в `gulp/i18n/locales/*.mjs` — по файлу на язык. Если указанный язык не поддерживается или в нём нет конкретной строки, используется английский (и как фоллбэк, и как язык по умолчанию). Технические метки в логах (`[Cache]`, `[DEBUG]`, названия сущностей) не переводятся — это грепабельные ярлыки, а не проза.

## Dependency Cache

```js
cache: {
  autoRebuild: true,   // строить кэш при старте dev-режима
  maxMemoryMB: 300,    // лимит памяти, при превышении - сброс кэша
  verbose: true,        // логировать обращения к кэшу
  debugTables: false,   // всегда выводить таблицы зависимостей, не только при новом анализе
}
```

Подробности — в разделе Dependency Cache.

## Runtime Monitor

```js
monitor: {
  maxMemoryMB: Math.round((os.totalmem() / 1024 / 1024) * 0.15), // 15% ОЗУ
  maxCpuPercent: CORES * 60,
  intervalMs: 10_000,
}
```

`os.totalmem()` всегда возвращает память ХОСТА — если Build System запущена в Docker-контейнере с ограничением по памяти, задайте реальный лимит явно через переменную окружения `DOCKER_MEM_LIMIT_MB` (см. раздел Docker): порог тогда считается от неё, а не от памяти хоста.

## Отладка

```js
debug: false;
```

Включает дополнительную диагностику. Не нужен при обычной разработке.
