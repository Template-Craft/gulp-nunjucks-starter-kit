# Build Pipeline

Последовательность этапов, через которые проходит проект во время сборки. Каждый этап отвечает за одну область и не зависит от внутренней реализации остальных.

```text
Reset
   │
   ▼
Assets Processing
   │
   ▼
Template Rendering
   │
   ▼
Output Generation
```

## Изоляция задач

Каждая gulp-таска отвечает только за один тип ресурсов: `styles` — за стили, `scripts` — за JS, `images`/`fonts` — за ассеты, `templates` — за HTML. Это позволяет менять или расширять один этап, не затрагивая остальные.

## Оркестрация

Последовательность и параллельность задают `gulp.series`/`gulp.parallel` в `gulpfile.mjs` — сам Pipeline не содержит бизнес-логики, он лишь объединяет независимые задачи.

## Полная и инкрементальная сборка

Полная сборка выполняется при `npm run build` или первом запуске `npm run dev`. Во время разработки работает инкрементальная сборка — обрабатываются только сущности, затронутые конкретным изменением (см. раздел Incremental Build).
