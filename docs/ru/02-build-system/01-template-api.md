# Template API

Слой абстракции между архитектурной моделью проекта и его физической структурой. Вместо относительных путей шаблоны обращаются к архитектурным сущностям через единый набор функций — Build System сам резолвит физическое расположение.

```njk
{% include getComponent("Header") %}
{% include getSection("about", "hero") %}
{% include getTemplate("head") %}
{% set siteData = getData("Global") %}
```

## Реализованные функции

| Функция                   | Назначение                                      |
| -------------------------- | ------------------------------------------------ |
| `getComponent(name)`       | Путь к шаблону Component.                        |
| `getSection(group, name)`  | Путь к шаблону Section (`group` пустой для Landing Page). |
| `getTemplate(name)`        | Путь к инфраструктурному Template.               |
| `getData(name)`            | Читает `src/views/data/<name>.json` и возвращает его как объект. |
| `jsonParse` (фильтр)       | `{{ value \| jsonParse }}` — парсит JSON-строку внутри шаблона. |

Все функции и фильтр регистрируются в среде выполнения Nunjucks при старте Build System (`gulp/tasks/templates.mjs`) и доступны в любом `.njk`-файле без дополнительного импорта.

## Почему не относительные пути

Относительные пути жёстко привязывают шаблоны к файловой структуре. Template API убирает эту зависимость: изменение структуры каталогов не требует правки существующих вызовов, потому что Build System сам разрешает архитектурный адрес в файл.
