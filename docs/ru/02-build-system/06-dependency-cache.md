# Dependency Cache

Хранит результат Dependency Analysis в памяти процесса и поддерживает его в актуальном состоянии, не пересканируя весь проект при каждом изменении.

```text
Initial Build
      │
      ▼
Dependency Analysis
      │
      ▼
Dependency Cache
      │
      ▼
───────────────
      │
      ▼
File Changed
      │
      ▼
Update Cache Entry
      │
      ▼
Incremental Build
```

## Как обновляется

При старте (`npm run dev`) выполняется полный анализ и кэш строится один раз. Дальше кэш обновляется двумя способами (`gulp/utils/updateDependencyMap.mjs`):

- **со стороны сущности** — при изменении самого файла-определения (например `Header.njk`) пересканируются уже известные пользователи этой сущности;
- **со стороны файла** (`syncFileUsages`) — при изменении ЛЮБОГО `.njk`-файла он сам пересканируется на все вызовы `getComponent`/`getSection`/`getTemplate`, и карта обновляется с его точки зрения. Это нужно, чтобы новый вызов, впервые добавленный в уже существующий файл, сразу попал в граф, а не ждал следующего полного ребилда.

Перед записью новая карта сравнивается со старой (`isSameMap`) — если ничего не изменилось, кэш не трогается и лишний лог не пишется.

## Защита по памяти

Кэш — это просто объект в памяти процесса, без TTL. Единственная защита от неограниченного роста — `settings.cache.maxMemoryMB` (`gulp/config/settings.mjs`): если `heapUsed` превышает порог, кэш сбрасывается целиком и строится заново при следующем обращении.
