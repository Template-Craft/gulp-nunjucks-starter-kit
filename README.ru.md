# gulp-nunjucks-starter-kit

> **Starter Kit, построенный вокруг архитектурного подхода к разработке сайтов на Nunjucks.**

## Почему появился этот проект

Большинство систем сборки автоматизируют процесс разработки: компилируют шаблоны, собирают стили, обрабатывают JavaScript и запускают локальный сервер.

Однако по мере роста проекта основную сложность начинают создавать не инструменты, а архитектура. Именно организация проекта, повторное использование компонентов, работа с данными и управление зависимостями определяют, насколько удобно развивать и сопровождать проект в дальнейшем.

**gulp-nunjucks-starter-kit** появился как результат многолетнего развития архитектурного подхода, сформированного в реальных коммерческих проектах.

Starter Kit не предлагает новую методику разработки. Он формализует архитектурные решения, которые уже доказали свою эффективность на практике, и предоставляет Build System, реализующую этот подход.

---

## Архитектура прежде всего

В основе проекта лежит простой принцип:

> **Архитектура определяет выбор инструментов, а не наоборот.**

Gulp, Nunjucks и остальные технологии рассматриваются исключительно как средства реализации архитектурных решений.

```text
Архитектура
      │
      ▼
Структура проекта
      │
      ▼
Соглашения об именовании
      │
      ▼
Template API
      │
      ▼
Dependency Graph
      │
      ▼
Incremental Build
      │
      ▼
Комфорт разработки
```

Именно эта идея лежит в основе Starter Kit и определяет все принимаемые архитектурные решения.

## Основные возможности

- Архитектурно-ориентированный подход к разработке.
- Единая структура проекта.
- Разделение проекта на Pages, Sections, Components и Templates.
- Централизованная организация данных.
- Template API.
- Автоматический анализ зависимостей.
- Dependency Graph.
- Incremental Build.
- Интеллектуальная точечная пересборка проекта.
- Полностью готовое окружение разработки.
- Интегрированные инструменты контроля качества кода.
- Подробная документация.

Все перечисленные возможности являются следствием единого архитектурного подхода, а не набором независимых функций.

## Цели проекта

Starter Kit создавался для того, чтобы:

- предоставить готовую архитектуру проекта;
- минимизировать первоначальную настройку;
- сократить количество рутинных действий;
- упростить сопровождение крупных проектов;
- обеспечить единые соглашения внутри команды;
- сделать процесс разработки более предсказуемым;
- позволить разработчику сосредоточиться на создании сайта, а не на настройке инструментов.

## Быстрый старт

### 1. Создание проекта

Репозиторий настроен как **GitHub Template Repository**.

Нажмите **Use this template** на GitHub, чтобы создать новый проект с уже готовой структурой каталогов, системой сборки и настроенным окружением разработки.

При необходимости репозиторий можно клонировать обычным способом.

### 2. Установка зависимостей

```bash
npm install
```

### 3. Запуск режима разработки

```bash
npm run dev
```

После запуска автоматически будет поднят локальный сервер разработки с поддержкой BrowserSync.

### 4. Открытие проекта

Откройте проект в Visual Studio Code.

Starter Kit уже содержит готовую конфигурацию рабочего пространства `.vscode`. Visual Studio Code автоматически предложит установить рекомендуемые расширения, поэтому дополнительная настройка практически не потребуется.

### 5. Ознакомление с документацией

Документацию рекомендуется читать в следующем порядке:

1. Philosophy
2. Architecture
3. Build System
4. Development
5. Guides
6. Development Tools

Такой порядок позволяет сначала понять архитектурные принципы проекта, затем устройство системы сборки и только после этого перейти к практическому использованию Starter Kit.

## Экосистема

Starter Kit может расширяться дополнительными инструментами.

Одним из таких проектов является **nsk-tools** — независимая CLI-утилита, автоматизирующая различные рутинные задачи разработки и не являющаяся частью Build System.

Такой подход позволяет развивать экосистему независимо, сохраняя сам Starter Kit лёгким и сфокусированным.
